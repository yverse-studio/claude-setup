## The new rule (one home: `.claude/skills/operator/gate.md`, Rounds)

one card to yskills. No round 7, no exception merge below the bar.

## What the best setups do

The same split everywhere: instructions guide, hooks enforce.

- Prose in `CLAUDE.md` is advisory and degrades as context grows; a `PreToolUse` hook that exits 2 is deterministic
  ([claude-code-mastery](https://github.com/TheDecipherist/claude-code-mastery), [claude-ctrl](https://github.com/juanandresgs/claude-ctrl): "Instructions guide. Hooks enforce.",
  [Your CLAUDE.md says always run tests: hooks are how you mean it](https://dev.to/rulestack/your-claudemd-says-always-run-tests-hooks-are-how-you-actually-mean-it-1o9f)).
- Loops get a counter held outside the model: Ralph-style loops keep `iteration` and `max_iterations` in a state file;
  Claude Code itself caps consecutive Stop-hook blocks (default 8, `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`)
  ([issue 59583](https://claudeissues.com/issue/59583-docs-stop-hook-docs-omit-consecutive-block-cap-and-override-env-var)). A cap that is itself
  unenforced fails (a Ralph loop ran 646 iterations, [issue 18086](https://claudeissues.com/issue/18086-bug-ralph-loop-max-iterations-not-respected-stop-hook-errors-with-empty-iteratio)).
- Escalation is rarely built in; the proposals ask for a harness-level override after N forced continuations
  ([issue 85547](https://claudeissues.com/issue/85547-stop-hook-block-cap-document-it-signal-the-override-to-hooks-and-bless-a-pattern)). Ours is explicit: round 3 → Fable director → round 6 → card.

Adopted (in #444, research table `docs/research/2026-11-12-loop-limits-and-hook-enforcement.md`): a counter held outside the model, a hook that reads it, escalation as the precondition of the next round.
